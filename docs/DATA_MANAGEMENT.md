# Portable data management

Settings exposes two owner-only controls under **Export or delete financial
data**.

## Portable export

**Download export** creates a gzip-compressed USTAR archive:

- `manifest.json` identifies the format, application/schema versions, export
  time, record counts, attachment count, and deliberate security exclusions.
- `README.txt` describes the layout and sensitivity.
- `records.ndjson` contains one `{ "type", "data" }` JSON object per line.
- `attachments/<attachment-id>/original[.png|.jpg|.webp]` contains each active
  stored file.

Only current, active financial records and owner-safe settings/options are
included. Password hashes, sessions, CSRF/token hashes, audit logs, rate-limit
state, idempotency journals, storage paths/object keys, backup secrets,
operational jobs, and backup artifacts are excluded. Attachment size and
SHA-256 are verified while the archive is assembled; an incomplete export is
discarded.

Treat the archive as private financial data. It is intentionally readable and
is not password-encrypted.

## Delete financial data

Deletion requires:

1. the current owner password;
2. the exact phrase `DELETE ALL DATA`;
3. the application CSRF token and exact configured origin; and
4. a UUID idempotency key generated by the client.

The transaction removes all live and soft-deleted expenses, subscriptions,
debts, payment histories, tags, attachment metadata, entity links, and their
write-request journals. Original files and image thumbnails are placed on the
durable attachment-cleanup queue.

The owner account, active session, regional preferences, categories, payment
methods, audit/security history, backup configuration, jobs, and backup
artifacts remain. Existing backups may therefore retain older financial data
and must be managed separately.

Purge refuses to start while any backup, preview, or restore job is queued or
processing. A retry with the same idempotency key returns the stored completed
result without deleting or auditing twice.
